## 목적

나를 소개하고 활동을 정리해 둘 수 있는 **개인 포트폴리오 사이트**를 직접 만들고,
정적 사이트 생성기(Hugo)와 Git·GitHub를 이용한 **빌드·배포 과정**을 익히는 것이 목적입니다.

## 진행 과정

1. **테마 선정** — Hugo Themes에서 자기소개·프로젝트·블로그 섹션이 모두 있는 *Hugo Profile* 테마를 골랐습니다.
2. **저장소 연결** — 테마를 내려받아 GitHub 저장소 `MyWebPage`에 연결했습니다.
3. **자동 배포 설정** — `main` 브랜치에 push하면 GitHub Actions가 Hugo로 사이트를 빌드하고 GitHub Pages에 배포하도록 워크플로를 구성했습니다.
4. **콘텐츠 교체** — 테마의 예시 데이터(가상 인물, 예시 글, 예시 이미지)를 모두 지우고 `hugo.yaml`에 내 정보를 넣었습니다.
5. **다국어 설정** — 한국어를 기본 언어로, 영어 페이지를 `/en/`에 두고 언어 전환 메뉴로 오갈 수 있게 했습니다.
6. **로컬 검증** — `hugo server`로 미리 보면서 메뉴·링크·검색·다크 모드가 동작하는지 확인했습니다.
7. **채점 기준으로 점검** — 공개 채점 기준과 실제 사이트를 하나씩 비교해, 아이콘만 있는 링크의 이름, 키보드 초점 표시, 목록 페이지 제목 구조 같은 접근성 문제를 찾았습니다.
8. **테마 원본을 보존하며 개선** — 테마 파일을 직접 고치지 않고 `site/layouts/`와 `site/static/css/custom.css`에 덮어쓰기 파일을 만들어 수정했습니다. 테마 출처·라이선스를 그대로 지키면서 내가 바꾼 부분을 분명히 구분하기 위해서입니다.
9. **자동 검사 추가** — 빌드 결과의 깨진 링크·이미지와 기본 접근성을 검사하는 스크립트(`tools/check_links.py`, `tools/check_a11y.py`)를 만들고, GitHub Actions가 배포 전에 실행해 문제가 있으면 배포를 멈추도록 했습니다.

## 문제 해결 기록

| 관찰한 문제 | 원인 | 해결 | 재확인 |
| --- | --- | --- | --- |
| 대표 활동 카드를 고쳤는데 미리보기 화면이 바뀌지 않음 | 미리보기 서버가 설정 파일을 다시 읽다가 멈춘 상태 | 서버를 다시 켜고, 결과물을 메모리에만 만들도록(`--renderToMemory`) 실행 방식 변경 | 새 카드 제목이 화면에 표시됨 |
| 활동 글 이미지가 배포 사이트에서 깨질 뻔함 | 이미지 경로를 내 PC 경로(`c:\Users\...`)로 적음 | 이미지를 `site/static/images/`로 옮기고 `/images/...` 경로로 변경 | 배포 사이트에서 이미지 200 응답 |
| 배포용 빌드 명령이 끝나지 않음 | 켜져 있던 미리보기 서버가 빌드 잠금 파일을 잡고 있음 | 미리보기를 끄고 빌드, `preview.ps1`이 실행 전 기존 서버를 종료하도록 개선 | 빌드 정상 완료 |
| 목록 카드의 세로 포스터가 납작하게 찌그러짐 | 테마가 이미지 높이만 250px로 고정 | `object-fit: cover`로 비율 유지 | 목록 화면에서 비율 유지 확인 |

## 결과

- `https://rldbs5353.github.io/MyWebPage/` 에서 사이트가 동작합니다.
- push할 때마다 자동으로 다시 빌드·배포됩니다.
- 한국어/영어 두 언어로 자기소개와 활동 기록을 볼 수 있습니다.
- 배포 전에 링크·접근성 자동 검사를 통과해야만 공개되며, 접근성 수정 전 86건이던 문제가 0건이 되었습니다.

## 배운 점

- 설정 파일 하나(`hugo.yaml`)로 사이트 전체 구조를 바꿀 수 있다는 점이 인상적이었습니다.
- GitHub Pages처럼 하위 경로(`/MyWebPage/`)에 배포할 때는 `baseURL`과 이미지·링크 경로를 신경 써야 한다는 것을 알게 되었습니다.
- AI를 활용해 설정과 오류 분석을 하면서도, 결과가 실제로 맞는지는 직접 빌드하고 확인해야 한다는 것을 느꼈습니다.
